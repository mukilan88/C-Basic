C Programming

02 - Compilation and Execution
🎯 Aim: To understand the journey a C program takes from human-readable source code to a running program — the stages a compiler performs, and the commands used to trigger them.
1. Why Can't the Computer Run C Code Directly?

A CPU only understands machine code — raw binary instructions specific to its hardware. The C code we write (like printf("Hello");) is designed for humans to read, not for the CPU. A special program called a compiler (e.g. GCC — the GNU Compiler Collection) translates our source code into machine code the CPU can actually execute.

2. The Four Stages of Compilation
1️⃣ Preprocessing
Handles all lines starting with # before real compilation begins.
program.c → program.i
Expands #include files (copies in the full content of stdio.h, etc.) and replaces #define macros with their literal values.
2️⃣ Compilation
Translates the preprocessed C code into Assembly language.
program.i → program.s
This is also where the compiler checks for syntax errors — missing semicolons, undeclared variables, mismatched types, etc.
3️⃣ Assembly
Converts the Assembly code into machine-readable Object code.
program.s → program.o
Object code is binary, but not yet a complete, runnable program — pieces are still missing.
4️⃣ Linking
Combines your object code with pre-compiled library code (like the real implementation of printf).
program.o + libraries → program (executable)
This is where linker errors appear — e.g. calling a function that was declared but never defined anywhere.
Source Code (.c) → Preprocessor → Compiler → Assembler → Linker → Executable File
3. Compiling & Running with GCC (Command Line)
# Step 1: Compile the source file into an executable
gcc program.c -o program

# Step 2: Run the executable
# On Linux / macOS:
./program

# On Windows:
program.exe
gcc → invokes the GNU C Compiler.
program.c → the source file to compile.
-o program → "output" flag; names the resulting executable file program (without -o, GCC defaults to naming it a.out).
./program → the ./ tells the shell "run the file named program located right here in this folder," which is required on Linux/macOS for safety reasons.
⚠ Compile-time vs Run-time
Compile-time is everything that happens during the gcc program.c -o program step — syntax errors are caught here, and the program never even gets created if these fail. Run-time is everything that happens after you launch ./program — a program can compile perfectly but still crash or misbehave at run-time (e.g. dividing by zero, reading beyond an array).
What if I don't have GCC installed?
You can also compile and run C instantly using free online compilers in a browser — no installation needed. This is exactly what the next topic, "Interactive and Script Mode," compares against writing and compiling a saved .c file yourself.
📝 One-Line Revision: Preprocessing → Compilation → Assembly → Linking turns your .c file into a runnable program; gcc file.c -o output then ./output is the standard command-line workflow.
