C PROGRAMMING

TOPIC 13: OPERATOR PRECEDENCE
🎯 Aim: To understand how operator precedence and associativity determine the exact evaluation order of an expression that mixes multiple operators, and how parentheses let us override the default order.
1. What is Operator Precedence?

When an expression contains more than one operator, C does not simply evaluate left to right — it follows a strict priority order called operator precedence, which decides which operator is evaluated first. Operators with higher precedence "bind tighter" and are calculated before operators with lower precedence, exactly like the "BODMAS"/"PEMDAS" rule you learnt in mathematics (multiplication before addition, for example).

#include <stdio.h>

int main() {
  int result;
  result = 10 + 5 * 2;
  printf("%d", result);
  return 0;
}
Output & Trace:
Step 1: * has higher precedence than +, so 5 * 2 is calculated first → 10
Step 2: Then the addition happens → 10 + 10 → 20

Final Output: 20
What if we actually wanted addition to happen first?
Wrap the part you want evaluated first inside parentheses: result = (10 + 5) * 2; → now 10 + 5 is forced to happen first (15), then multiplied by 2, giving 30 instead of 20. Parentheses always have the highest precedence of all, which is exactly why they are the standard tool for making your intended evaluation order explicit and bug-free.
2. What is Associativity?

Precedence decides which operator goes first when operators differ. But what happens when two operators of the same precedence appear next to each other, like 20 - 5 - 3? That's where associativity comes in — it decides the direction (left-to-right or right-to-left) in which same-priority operators are grouped. 20 - 5 - 3 is left-to-right associative, so it's grouped as (20 - 5) - 3 = 12, not 20 - (5 - 3) = 18.

⚠ Correction / Extra Detail: The original quick-reference table only listed 10 broad groups and merged all bitwise operators together with logical operators. In real C precedence rules, bitwise AND (&), XOR (^), and OR (|) each sit at their own, separate priority level — all below relational/equality but above logical &&/||. The ternary operator ?: is also lower priority than all of those, and assignment is the lowest of all (besides the comma operator, which is beyond this topic). The full 14-row table above is the complete and accurate version.
4. Worked Example Using Both Rules Together

Consider: int x = 2 + 3 * 4 > 10 && 5 == 5;

Step 1 (Multiplicative, priority 3): 3 * 4 → 12
Step 2 (Additive, priority 4): 2 + 12 → 14
Step 3 (Relational, priority 6): 14 > 10 → 1 (true)
Step 4 (Equality, priority 7): 5 == 5 → 1 (true)
Step 5 (Logical AND, priority 11): 1 && 1 → 1 (true)
Step 6 (Assignment, lowest priority): x = 1
💡 Pro Tip — Don't Memorise, Use Parentheses:
Even experienced programmers rarely memorise every row of this table. The safest and most readable habit is: whenever an expression mixes more than two different operator types, add parentheses to make your intended order explicit — e.g. (10 + 5) * 2 instead of relying on everyone remembering that * beats +. This prevents bugs and makes code easier for others (and your future self) to read.
📝 One-Line Revision: Precedence = which operator goes first when they differ | Associativity = which direction to group when they're equal | Parentheses always win and should be used generously for clarity.
