07 - Data Types (Part 2 of 3): Integer Types & Size Modifiers
🎯 What will we learn? How C offers several "flavours" of the integer type (short, normal, long, long long — each signed or unsigned) so we can pick the right size for the numbers we need to store, without wasting memory.
1. Why Do We Need Different Integer Sizes?

A plain int is usually enough, but sometimes we need to save memory (e.g. storing thousands of small numbers, so short is enough) or we need to store numbers far bigger than int can hold (e.g. a national population, so we need long long). The size modifiers — short, long, long long, and signed/unsigned — let us control exactly how much memory a whole number uses and whether it can be negative.

2. Integer Types & Meaning
1. short int (Small whole number)
short int a = 10;
Format Specifier: %hd
2. unsigned short int (Positive only, small)
unsigned short int b = 50;
Format Specifier: %hu
3. int / signed int (Normal integer, most common)
int c = -200;
Format Specifier: %d
4. unsigned int (Positive normal integer)
unsigned int d = 400;
Format Specifier: %u
5. long int (Large whole number)
long int e = 100000L;
Format Specifier: %ld
6. unsigned long int (Large positive only)
unsigned long int f = 200000UL;
Format Specifier: %lu
7. long long int (Very large whole number)
long long int g = 9000000000LL;
Format Specifier: %lld
8. unsigned long long int (Very large, positive only)
unsigned long long int h = 18000000000ULL;
Format Specifier: %llu
💡 What do "signed" and "unsigned" actually mean?
Every integer type reserves a fixed number of bits. signed (the default) splits that range between negative and positive numbers, so it can represent both. unsigned gives up the ability to store negatives, and in exchange uses that freed-up range to store larger positive numbers — roughly double the positive range of the signed version. Use unsigned only when you are certain the value can never be negative (e.g. a count of students, an array index, a byte size).

⚠ Correction / Important Note: The exact byte size of int and long int is technically compiler and system dependent — the C standard only guarantees a minimum size. On almost every modern system you will use (64-bit Linux/GCC, which Voflic students typically compile on), int is 4 bytes and long int is 8 bytes, as shown above. Always confirm with the sizeof() operator (covered in the next topic) rather than memorising numbers blindly.
4. Simple C Program & Output
#include <stdio.h>

int main() {
  short int a = 10;
  int b = 100;
  long int c = 1000;
  long long int d = 10000;

  unsigned int e = 500;

  printf("short int = %hd\n", a);
  printf("int = %d\n", b);
  printf("long int = %ld\n", c);
  printf("long long int = %lld\n", d);
  printf("unsigned int = %u\n", e);

  return 0;
}
Output:
short int = 10
int = 100
long int = 1000
long long int = 10000
unsigned int = 500

Note: Even though these small values (10, 100, 1000...) would fit into any of the types, declaring them as short, long, long long here is only to demonstrate the correct declaration syntax and matching format specifier for each type — not because these particular numbers need that much space.
Why does the literal number need a suffix like L, UL, LL, ULL?
By default, a plain number like 100000 is treated by the compiler as an int. If that number is too big to fit in an int but we are assigning it to a long long, the suffix tells the compiler "treat this literal itself as a long/long long/unsigned value" so no data is lost during the calculation, even before it reaches the variable.
  • 100000L → treat as long
  • 200000UL → treat as unsigned long
  • 9000000000LL → treat as long long
  • 18000000000ULL → treat as unsigned long long
💡 Important Rules to Remember:
• signed = stores both negative and positive numbers (this is the default if you don't write "unsigned").
• unsigned = stores ONLY positive numbers (0 and above), which roughly doubles the maximum positive value compared to the signed version.
• Always match the printf()/scanf() format specifier to the exact variable type — mismatching them (e.g. printing a long long with %d) gives wrong/garbage output, especially for large numbers.
• Use the correct suffix for large literals: L (long), UL (unsigned long), LL (long long), ULL (unsigned long long).
