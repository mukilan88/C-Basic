C Programming

01 - Structure of a C Program
🎯 Aim: To understand the standard sections every C program is built from, in the order the compiler expects them, and why each section exists.
1. Why Does a C Program Need a "Structure"?

C is not a free-form language — the compiler expects code to be organised into specific sections, in a specific order. Learning this fixed skeleton means you can look at any C program, even one you've never seen, and immediately recognise where the includes are, where variables live, and where execution actually starts.

2. The Six Sections of a C Program
1. Documentation Section
Comments describing what the program does, author name, date. Optional but good practice.
2. Preprocessor / Link Section
#include statements that bring in library code, e.g. #include <stdio.h>.
3. Global Declaration Section
Variables or function prototypes declared outside main(), visible to every function in the file.
4. main() Function Section
int main() { ... } — the compulsory entry point. Execution always begins here.
5. Local Declaration & Statements
Variables declared inside main() (or any function), followed by the actual instructions (executable statements).
6. User-Defined Function Section
Any additional functions you write yourself, usually placed after main().
3. Annotated Example
// Documentation Section
// Program: Add two numbers
// Author: Voflic Academy

/* Preprocessor / Link Section */
#include <stdio.h>

/* Global Declaration Section */
int total; // visible to every function below

/* main() Function Section */
int main() {
  // Local Declaration
  int a = 5, b = 10;

  // Executable Statements
  total = a + b;
  printf("Total = %d\n", total);

  return 0;
}
Documentation is written as comments — the compiler skips these entirely, they exist purely for humans reading the code.
#include <stdio.h> must appear before you use printf()/scanf(), since the compiler needs to know these functions exist before it sees them being called.
int total; declared outside main() is a global variable — it exists for the entire lifetime of the program and can be accessed inside any function, unlike a local variable which only exists inside the function it's declared in.
int main() is the only section that is truly compulsory — every single C program must have exactly one main(), because that's where the operating system hands control to your program.
return 0; tells the operating system the program finished successfully. A non-zero return generally signals that something went wrong.
💡 What is actually compulsory vs optional?
  • Compulsory: the main() function. A C program with no main() will not compile into a runnable program.
  • Practically necessary: #include <stdio.h> — only if you use input/output functions like printf/scanf.
  • Optional: documentation comments, global variables, and user-defined functions — a tiny program can consist of nothing but an empty main().
Curly braces { } define a "block."
Everything between the opening { and closing } of main() belongs to that function. Every opening brace must have a matching closing brace — a missing one is one of the most common beginner compile errors (covered in Topic 16).
📝 One-Line Revision: Documentation → Preprocessor → Global Declarations → main() → Local Declarations & Statements → User-Defined Functions — in that order, with main() as the only compulsory piece.
