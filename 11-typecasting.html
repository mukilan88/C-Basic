TOPIC 11: TYPE CASTING (Implicit & Explicit)
🎯 Aim: To understand what type casting is, the difference between implicit and explicit casting, and how to avoid the classic "integer division" trap that silently produces wrong results.
1. What is Type Casting?

Type casting is the process of converting a value from one data type into another — for example, converting an int into a float, or a float into an int. This is needed because C is strict about types: mixing types in a calculation or assignment requires the value to first be converted so both sides "speak the same language." There are two ways this conversion can happen:

  • Implicit type casting — the compiler converts it automatically, without you asking.
  • Explicit type casting — you, the programmer, manually force the conversion.
⚙ 1. Implicit Type Casting (Automatic)
Performed automatically by the C compiler, usually when a "smaller" type is combined with or assigned to a "larger" type — this is called type promotion. No data is lost in this direction.
int a = 10;
float b = a; // Auto converted to float
int (10) → Compiler → float (10.000000)
Output: Integer value: 10
Float value: 10.000000
✍ 2. Explicit Type Casting (Manual)
The programmer forces conversion using the cast operator (type)value. Used when going from a "larger" type to a "smaller" one, where data (like the decimal part) may be lost — the compiler will not do this automatically because it could silently lose information, so it requires an explicit request.
float a = 10.75;
int b = (int)a; // Drops .75 decimal
float (10.75) → (int) → int (10)
Output: Float value: 10.750000
Integer value: 10
Why does casting float to int give 10, not 11?
Explicit (int) casting always truncates — it simply chops off everything after the decimal point. It does not round to the nearest whole number. So (int)10.75 gives 10, and even (int)10.99 would still give 10, not 11.
Casting Type Who Performs It? Syntax / Example Key Takeaway
Implicit Compiler float b = a; Automatic promotion, safe (no data loss going small → large)
Explicit Programmer int b = (int)a; Manual conversion operator, may lose data (large → small)
2. The Classic Trap: Type Casting in Division

Why does 5 / 2 output 2.000000 instead of 2.500000 in C, even when the result is stored in a float?

❌ Without Casting (Integer Division)
int a = 5, b = 2;
float c;
c = a / b;
Evaluation steps:
  1. a / b is calculated first, before any assignment happens.
  2. Since both a and b are int, C performs integer division: 5 / 2 mathematically is 2.5, but integer division discards the decimal part, giving 2.
  3. Only after this truncated integer result (2) is computed does the assignment to the float variable c happen — so c becomes 2.000000, and the .5 is already permanently lost by that point.
Output: 2.000000
✅ With Explicit Casting (Floating Division)
int a = 5, b = 2;
float c;
c = (float)a / b;
Evaluation steps:
  1. (float)a converts a from 5 (int) to 5.0 (float) before the division happens.
  2. Now the expression is 5.0 / 2 — since one operand is already a float, C automatically promotes b to float as well and performs floating-point division.
  3. Result is the mathematically correct 2.500000, stored fully in c.
Output: 2.500000
💡 Core Teaching Rule: Casting just one operand before an arithmetic calculation (e.g., (float)a / b) is enough to make the entire expression evaluate as floating-point — C automatically promotes the other operand to match. You do NOT need to cast both sides.
⚠ Common Beginner Mistakes with Casting
  • Writing c = (float)(a / b); instead of c = (float)a / b; — this casts the already-truncated integer result to float too late; you still get 2.000000, not 2.500000. The cast must happen before the division, on one of the operands.
  • Assuming (int) rounds — it truncates (always rounds toward zero), which is not the same as rounding to the nearest whole number.
  • Forgetting that casting a double down to float, or a large long long down to int, can lose precision or overflow — explicit casting removes the compiler's safety warning, so the responsibility shifts to the programmer.
3. Quick Memory Flowchart
IMPLICIT → Automatic → Compiler decides
EXPLICIT → Manual → Programmer writes (type)
📝 One-Line Revision: Implicit = automatic, safe, compiler-driven conversion | Explicit = manual, programmer-driven conversion using (type)value | (float)5 / 2 = 2.5, but 5 / 2 = 2.
