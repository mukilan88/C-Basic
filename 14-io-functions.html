14 - Input/Output Functions
✦ Aim: To understand what Input/Output (I/O) functions are in C, where they come from, and the main functions available — before diving into the detailed formatted versions in the next topic.
1. What is an Input/Output Function?

A program is only useful if it can exchange data with the outside world: reading what the user types (input) and showing results back (output). C does not build this ability into the language itself — instead, it is provided through library functions declared in the header file stdio.h ("Standard Input Output"), which is why every program that reads or displays anything begins with #include <stdio.h> (Topic 1).

2. The Main I/O Functions in C
Function Direction Reads/Writes Notes
printf() Output Formatted text of any type The most-used output function; covered in depth next topic
scanf() Input Formatted values of any type The most-used input function; covered in depth next topic
getchar() Input A single character Simplest possible input — no format specifier needed
putchar() Output A single character Simplest possible output — no format specifier needed
gets() (unsafe, avoid) Input A full line of text, including spaces Removed from modern C standards due to buffer-overflow risk
fgets() Input A full line of text, safely, up to a size limit The modern, safe replacement for gets()
puts() Output A string, followed automatically by a newline Simpler than printf() when no formatting is needed
3. Simple I/O Without Any Format Specifiers
#include <stdio.h>

int main() {
  char ch;

  puts("Type a character: ");
  ch = getchar(); // reads exactly one character

  puts("You typed:");
  putchar(ch); // writes exactly one character

  return 0;
}
getchar() and putchar() work with a single character at a time — no format string like "%c" needed, since there's only one possible type they can handle.
puts() prints a string and automatically adds a newline afterward — unlike printf(), which requires you to add \n yourself.
These simpler functions are useful when you don't need C's flexible formatting — just plain text or a single character.
⚠ Why avoid gets()?
gets() reads a whole line but has no way to limit how many characters it accepts — if the input is longer than the destination array, it silently overflows into other memory, a serious security risk. Modern C standards have removed it entirely. Use fgets() instead, which takes a maximum size argument.
Why is printf()/scanf() so much more common than the simple functions?
getchar()/putchar() only handle single characters, and puts() only handles plain strings. Real programs constantly need to read/display numbers (int, float, double) alongside text — that flexibility is exactly what printf() and scanf() provide through format specifiers, which is the focus of the next topic.
📝 One-Line Revision: I/O functions live in stdio.h and move data between your program and the user — getchar()/putchar()/puts() handle simple cases, while printf()/scanf() handle everything via formatted specifiers (next topic).
