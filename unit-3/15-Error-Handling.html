PAGE 15: ERROR HANDLING IN FILE OPERATIONS
🎯 Aim: To prevent unexpected program crashes by detecting, diagnosing, and gracefully handling file runtime errors such as missing files, permissions issues, disk-full faults, and distinguishing between true I/O errors and natural End-Of-File (EOF).
1. Why Error Handling Matters in File I/O?

Unlike variables in RAM which are always accessible, files live in secondary storage controlled by the Operating System. File operations can fail for many external reasons: a deleted file, bad permissions, or a disconnected USB drive. Every file stream maintains internal status flags to track what happens during read/write calls:

🏴 EOF Flag (feof)
Set when a read operation tries to read past the final byte of the file. Not an error — just marks the end!
⚠ Error Flag (ferror)
Set when a physical hardware or stream failure occurs (e.g., writing to a read-only file or corrupted disk sector).
2. The 4 Essential Error-Checking Tools
👁 1. feof(fp)
Returns non-zero if the file pointer has reached the End of File.
⚠ 2. ferror(fp)
Returns non-zero if an I/O error occurred on the stream.
📢 3. perror(str)
Prints your custom message followed by OS error explanation.
🔄 4. clearerr(fp)
Resets both EOF and error flags back to 0 for retry.
3. Complete Program: Detecting Missing Files & Reading Safely
#include <stdio.h>
#include <stdlib.h>

int main() {
    FILE *fp;
    char filename[30], ch;

    printf("Enter file name to open: ");
    scanf("%s", filename);

    // 1. Check for NULL pointer on fopen()
    fp = fopen(filename, "r");
    if (fp == NULL) {
        perror("Error"); // Prints system error description
        return 1;
    }

    // 2. Read characters and monitor stream flags
    printf("\nFile Contents:\n");
    while ((ch = fgetc(fp)) != EOF) {
        putchar(ch);
    }

    // 3. Diagnose why the loop stopped
    if (ferror(fp)) {
        printf("\nError: An I/O error occurred while reading!\n");
    } else if (feof(fp)) {
        printf("\nReached End of File successfully.\n");
    }

    fclose(fp);
    return 0;
}
💻 Terminal Case 1 (Missing File):
Enter file name to open: test.txt
Error: No such file or directory

💻 Terminal Case 2 (Successful Read):
Enter file name to open: sample.txt
File Contents:
Hello C Programmers!
Reached End of File successfully.
🔍 What Does perror() Do?
• When any system call fails, C sets a global error integer named errno.
• perror("CustomMsg") converts that code into plain English (e.g. "Permission denied" or "No such file or directory") and prints it automatically!
4. Quick Error Function Comparison Table
Function Prototype Header When to Call It? Return Value
int feof(FILE *fp); <stdio.h> After a read operation finishes Non-zero if EOF reached, else 0
int ferror(FILE *fp); <stdio.h> After reading or writing to verify stream integrity Non-zero if an error occurred, else 0
void perror(const char *s); <stdio.h> Immediately after fopen() == NULL None (prints error string directly to stderr)
void clearerr(FILE *fp); <stdio.h> Before retrying an operation on the same stream None (clears both EOF and error flags)
⚠ The while(!feof(fp)) Trap (Common Exam Bug):
feof() only returns true after a read attempt fails by hitting past EOF. Using while(!feof(fp)) { fscanf(...); print(...); } will process the last line twice! Always test the return of the read function: while(fscanf(...) == 1).
💡 Always Guard fopen() with NULL Check:
Never use fp without testing if (fp == NULL) first! Passing a NULL pointer to fgetc() or fprintf() results in an immediate Segmentation Fault / crash!
📝 One-Line Summary: Check fp == NULL after opening; use perror() for human-readable error messages, and verify feof() vs ferror() to distinguish EOF from disk failures.
