🎯 Aim: To understand how text files differ from binary files in secondary storage, see how data types are converted or preserved, and perform raw block input/output using fwrite() and fread().
1. How Data is Stored: Text vs. Binary

In C, files are classified by how information is encoded onto the disk. Text files translate values into human-readable ASCII/UTF characters. Binary files dump the exact raw bytes from RAM directly to disk with zero conversion.

📄 Text File (.txt) – Number 12345
Stored as 5 distinct character codes (1 byte each):
'1' (49)
'2' (50)
'3' (51)
'4' (52)
'5' (53)
Requires 5 Bytes • Readable in Notepad
💾 Binary File (.bin / .dat) – Number 12345
Stored directly as 4 raw memory bytes (int in RAM):
0x39
0x30
0x00
0x00
Requires 4 Bytes (fixed) • Opens as raw/gibberish symbols
2. Complete Binary File Program (fwrite and fread)
#include <stdio.h>

struct Player {
    int id;
    char name[20];
    int score;
};

int main() {
    FILE *fp;
    struct Player p1, p2;

    // 1. Reading runtime values to write
    printf("Enter ID, Name, Score: ");
    scanf("%d %s %d", &p1.id, p1.name, &p1.score);

    // 2. Writing raw struct block to binary file ("wb")
    fp = fopen("game.dat", "wb");
    fwrite(&p1, sizeof(struct Player), 1, fp);
    fclose(fp);
    printf("Binary record written successfully.\n\n");

    // 3. Reading exact raw block back ("rb")
    fp = fopen("game.dat", "rb");
    fread(&p2, sizeof(struct Player), 1, fp);
    fclose(fp);

    printf("--- Read from Binary File ---\n");
    printf("ID: %d | Name: %s | Score: %d\n", p2.id, p2.name, p2.score);
    return 0;
}
💻 Terminal Execution (Runtime):
Enter ID, Name, Score: 7 Dhoni 183
Binary record written successfully.

--- Read from Binary File ---
ID: 7 | Name: Dhoni | Score: 183
🔍 Syntax of fwrite() & fread()
Both functions take 4 arguments:
fwrite(ptr, size, count, fp);
• ptr: Address of source/target memory buffer.
• size: Size in bytes of one record (sizeof).
• count: Number of records to transfer.
• fp: Target FILE* stream pointer.
3. Key Differences: Text File vs. Binary File
Aspect Text Files Binary Files
Storage Format Plain text (ASCII or UTF-8 characters) Exact binary memory image (0s and 1s)
Human Readability Easily opened & edited in text editors (Notepad) Unreadable directly; opens as gibberish symbols
I/O Functions fprintf(), fscanf(), fputs(), fgets() fwrite(), fread()
Opening Modes "r", "w", "a" "rb", "wb", "ab" (notice the 'b'!)
Speed & Efficiency Slower (requires number ↔ text conversions) Much faster (direct RAM-to-disk block transfer)
End-of-Line Conversion Converts \n to \r\n automatically on Windows No newline transformation; raw bytes preserved
⚠ Forgetting the 'b' in File Modes:
Always include 'b' in mode strings ("wb", "rb") when working with binary files! On Windows, omitting 'b' makes the OS treat byte 0x1A as EOF and alters newline bytes, corrupting your data.
💡 Why Binary is Best for Structs:
Writing a structure to a text file requires formatting each field with fprintf. With binary files, one single line: fwrite(&s, sizeof(s), 1, fp); saves the whole record instantly in one CPU block!
📝 One-Line Summary: Text files store characters readable by humans; binary files store raw bytes using fwrite() and fread() with modes like "wb" and "rb" for faster, compact storage.
