🎯 Aim: To achieve permanent data storage by creating and connecting to files on the secondary storage drive (Hard Disk) using C's standard file stream pipeline: fopen(), fprintf(), fscanf(), and fclose().
1. Why Files? & The 4-Stage File Lifecycle

Variables in RAM vanish the instant a program terminates (Volatile Memory). Files store data persistently on non-volatile disks. Communication between C code and a disk file operates through an OS buffer called a Stream managed via a FILE* handle.

2. Complete Runtime Program (Write then Read from File)
#include <stdio.h>

int main() {
    FILE *fp;
    int roll, readRoll;
    char name[30], readName[30];

    // --- PART 1: WRITING DATA TO FILE ---
    fp = fopen("student.txt", "w");
    if (fp == NULL) { printf("Error opening file!\n"); return 1; }

    printf("Enter Roll No & Name to write: ");
    scanf("%d %s", &roll, name);
    fprintf(fp, "%d %s\n", roll, name); // Writes to disk
    fclose(fp); // Flushes buffer and saves
    printf("Data saved to student.txt successfully.\n\n");

    // --- PART 2: READING DATA FROM FILE ---
    fp = fopen("student.txt", "r");
    if (fp == NULL) { printf("File not found!\n"); return 1; }

    fscanf(fp, "%d %s", &readRoll, readName); // Reads back
    printf("--- Data Read from Disk File ---\n");
    printf("Roll: %d | Name: %s\n", readRoll, readName);
    fclose(fp);
    return 0;
}
💻 Terminal Execution (Runtime):
Enter Roll No & Name to write: 101 Mukilan
Data saved to student.txt successfully.

--- Data Read from Disk File ---
Roll: 101 | Name: Mukilan
🔍 Why fclose() is Critical
• C holds file writes in a temporary RAM buffer for speed.
• fclose(fp) forces the OS to physically write (flush) any remaining data to the hard disk.
• Failing to close a file risks data loss and leaves OS file locks open!
3. Fundamental File Access Modes in C
Mode Meaning / Action What happens if file doesn't exist? What happens to existing data?
"r" Read only Returns NULL (Cannot open) Preserved (Read-only access)
"w" Write only Creates a new empty file Erased! (Overwrites everything)
"a" Append (add to end) Creates a new empty file Preserved (Appends new data to end)
"r+" Read + Write Returns NULL Preserved (overwrites from start)
⚠ The "w" Mode Danger Trap:
Opening a file with mode "w" immediately truncates the file size to 0 bytes! Any previous contents are wiped instantly. If you want to keep old data and add new records, always choose mode "a" (append).
💡 Console vs File I/O Parallel:
Notice how simple the syntax bridge is:
• printf(...) ↔ fprintf(fp, ...)
• scanf(...) ↔ fscanf(fp, ...)
You only add the FILE *fp argument as the first parameter!
📝 One-Line Summary: File handling persists data to disk: use fopen() with appropriate mode, write with fprintf() or read with fscanf(), and always close with fclose().
